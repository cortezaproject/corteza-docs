= `2026.9.0`

*Released on*: `TBD`

[IMPORTANT]
====
.[#2026_09_00-important]#<<2026_09_00-important,Important upgrade notes:>>#
* Security fixes in this release are not backported to `2024.9`. Upgrade to `2026.9.0` to receive them.
* Users can only change their own name, handle, language, theme and avatar. Changing own email, username, user group, kind or labels requires permission to update users; such changes are ignored and logged as a warning. Workflows that update these fields on the user who triggered them must run as a user with that permission (Run as).
* Contextual role expressions can only use `user.email` (empty until the email is confirmed) and `user.labels`. Expressions using `user.name`, `user.handle` or `user.username` no longer match and need to be rewritten, for example with labels.
* Auth clients without redirect URIs only accept redirects to the address of the server (`AUTH_BASE_URL`) and the webapp domain (`DOMAIN_WEBAPP`). When web applications are served from another address, such as a separate domain or a local development server, list it in the new `AUTH_DEFAULT_REDIRECT_URIS` option or set redirect URIs on the auth client. Redirect URIs now need to match scheme, host and port exactly.
* Corredor scripts that define `security.allow` can only be listed and run by users with one of the allowed roles. Denied roles still take precedence and super administrators are not limited by the list.
* Making a workflow run as another user requires the impersonate permission on that user, this includes importing such workflows. Changing the owner of a workflow requires the grant permission on automation.
* Workflow HTTP request and OAuth2 functions and the API Gateway proxy can no longer reach link-local addresses, which includes cloud metadata endpoints. Use the new `HTTP_CLIENT_RESTRICTED_NETWORKS` option to also block private networks (`private`) or to lift the restriction (`none`).
* Reading a Compose attachment over the API requires read permission on its namespace, removing it requires being its uploader or update permission on the namespace. Workflows removing attachments are subject to the same rule. Attachments, modules, pages and page layouts can only be accessed through the namespace they belong to.
* Removing system attachments over the API requires permission to manage settings. Avatars can be removed by their owner and by users with permission to update the owner.
* Sending email notifications over the API, which is what Corredor scripts use, requires the new Send email notifications permission on Compose. Fresh installations grant it to administrators; on existing installations grant it to the roles whose scripts send email. Workflows sending email are not affected.
* Creating or updating an auth client that impersonates another user requires the impersonate permission on that user, and every newly forced role requires permission to manage members of that role. Reading and regenerating the secret of an auth client requires permission to update it.
* Editing translations of Compose resources requires permission to update the resource or permission to manage resource translations, and only translations of the resource being edited are accepted.
* Reading a role over the API requires read permission on that role. Listing role membership of a user requires read permission on the user and only returns roles that can be read.
* SCIM endpoints are only available when `SCIM_SECRET` is set.
* Managing federation nodes requires the matching federation permissions and pairing requires a pairing token. Paired nodes can only synchronise data that is shared with them.
* Record reports are rejected when they use fields the user is not allowed to read. Reading workflow execution traces requires permission to update the workflow.
